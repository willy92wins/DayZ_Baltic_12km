## Árbol de archivos y publicaciones parciales

Directorio de salida exclusivo, diferente de logs externos. Nombres deterministas:
- header.json (identidad del contrato, NPZ, módulos, universo, claims fijos).
- chain-0000/ a chain-1029/: cache.json, queries-0000.ndjson ... y terminal.json.
- manifest.json al terminar todas las cadenas.

No carpetas, archivos ni enlaces extra. JSON de control/cache se escribe primero a nombre terminado .tmp en el mismo directorio, flush+fsync del archivo y os.replace sólo hacia destino que aún no existe bajo el único escritor propietario. Query shards son append exclusivo, cada línea JSON completa con LF; flush+fsync al cerrar. Terminal se publica después de cerrar todos los archivos de su cadena. No prometer atomicidad o durabilidad de directorio no medida: el consumidor verifica contenido y vínculos después. Manifest sólo después de verificar localmente que existen los1030terminales. No reanudar una ejecución consumida automáticamente.

Consumidor posterior con productor ya terminado: verifica header, luego cadena0,1,... . Un terminal ausente permite PARTIAL sólo si todas las cadenas anteriores tienen terminal válido y no hay ninguna cadena posterior al primer hueco. El directorio de ese primer hueco puede contener únicamente cache/shards/.tmp de nombres válidos y caps respetados: se enumera como unverified_tail, nunca se consume como evidencia numérica. Un terminal presente pero inválido es rechazo, no un hueco benigno. Sólo un manifest.json.tmp ausente de publicación final puede permanecer como cola no verificada; manifest.json presente se valida estrictamente. Falsificar FULL, hash, secuencia, archivo extra, terminal inválido o query omitida se rechaza. El consumidor no promete rescatar un prefix si el layout viola el contrato.

## Campos cerrados de registros

header: schema=q02b3.v1, kind=header, contract_sha256, npz_sha256, helpers, universe, claims. Claims literales: human_cases={count:9,state:GEOMETRY_UNBOUND,resolved:0}, controls=4,c1=NOT_REVIEWED,natural_positive_count=0,calibration_ready=false,angle_state=PENDING_CERTIFIED_ANGLE,map_repaired=false. Consumidor verifica todos los valores y no lee capturas humanas opcionalmente.

cache: objeto del esquema sellado Q02B2: meta,closed,points,edges,pref_lo,pref_hi,degenerate_indices,counters. meta exactamente {chain_id,point_offset,segment_offset,core_count,core_float64_le_sha256,npz_sha256,contract_sha256}. Points son ratios exactos de float64 del NPZ. Cierre se valida bit a bit antes de quitar repetición final. Consumidor NO usa prefijos para localizar; sí verifica sus sumas contra aristas como evidencia adicional. Recalcula q=dx²+dz² y cada certificado raíz. Counters productor tipados/acotados pero no transcript ni igualdad de multiplicidad.

query: {kind:query,chain_id,center,h,result}. Orden: center ascendente y, dentro, h contractual. result es la semántica sellada {state,stations,features,support,ops}, comparada campo a campo por el nuevo consumidor salvo ops, que debe ser int dentro del cap. No aceptar campos numéricos inventados ni sustituir FALSE por0. Si la aritmética del productor agota su cap: result={state:RESOURCE_INCONCLUSIVE,stations:null,features:null,support:null,ops:null,reason:query_budget}. Este registro sólo prueba que se declaró agotamiento; no prueba que se consumiera realmente el presupuesto. El consumidor conserva esa limitación y no convierte dicha consulta en cálculo verificado, aunque su cálculo propio pueda completarse. No se aceptan otras razones genéricas para ocultar errores de código.

terminal: {kind:chain_terminal,chain_id,contract_sha256,selector_sha256,classification,universe,query_count,excluded_count,state_counts,cache,shards,unverified_numeric_count}. selector_sha256 es SHA del JSON canónico de ese selector (UTF8, sorted keys, separators(',',':'), sin LF). cache es null o {name:cache.json,bytes,sha256}; shards lista ordenada {name,bytes,sha256,queries}. El consumidor deriva universe=core_count*5 y todos los conteos, no confía en el terminal.

Clasificación NUMERIC: cache verificada; una query por cada par contractual. Estados permitidos los del núcleo (DEFINED,UNDEFINED_ZERO_CHORD,INSUFFICIENT_SUPPORT,SUPPORT_UNCERTAIN,BOUNDARY_UNCERTAIN,OUT_OF_RANGE) y RESOURCE_INCONCLUSIVE; INVALID_QUERY es fallo para selectores válidos. Recurso del consumidor también deja resultado numérico no verificado explícito, nunca PASS matemático. Consultas definidas incluyen certificados de rasgos verificados por evaluación independiente.

Clasificación DEGENERATE: cache verificada con indices de q<THR² recomputados, sin shards, query_count0, excluded_count=universe, state_counts={DEGENERATE:universe}. No es exclusión aceptada por etiqueta histórica sola. Se contabiliza la causa, no calidad. Clasificación RESOURCE_INCONCLUSIVE de cadena: sin cache ni shards, query_count0, excluded_count=universe,state_counts={RESOURCE_INCONCLUSIVE:universe},unverified_numeric_count=universe. No certifica agotamiento real; afecta al veredicto como no verificado. Dato estructural inválido/contradicción de pin detiene la captura con error externo, sin fabricar un terminal de recurso.

manifest: {kind:manifest,schema:q02b3.v1,contract_sha256,npz_sha256,chain_count,universe,query_count,excluded_count,state_counts,unverified_numeric_count,terminals}. terminals lista ascendente {chain_id,bytes,sha256}; counts suman exactamente los terminales. No guardar path absoluto ni aceptar lista truncada como FULL. Cada archivo contabilizado una vez; la suma de bytes de archivos existentes, incluidos temporales, respeta2GiB.

## Veredicto independiente

Separar cobertura enumerada de verificación numérica. Una captura con 1030terminales y manifest válido puede tener coverage_complete=true; si existe cualquier declaración RESOURCE no verificada, su estado final es NUMERIC_RESOURCE_INCONCLUSIVE, no VERIFIED_FULL_NUMERIC_COVERAGE_ONLY. Lo mismo si el consumidor agota su presupuesto durante una consulta. VERIFIED_FULL_NUMERIC_COVERAGE_ONLY exige cobertura completa y cero registros numéricos no verificados. VERIFIED_PARTIAL_NUMERIC_COVERAGE sólo certifica el prefijo íntegro comprobado, con completed_chains,universo cubierto y cola no verificada explícitos; nunca aceptación del resto. Si el prefix contiene recursos no verificados, usar NUMERIC_RESOURCE_INCONCLUSIVE con cobertura parcial, no ocultarlos bajo VERIFIED_PARTIAL. TIMEOUT externo conserva archivos pero no demuestra esos estados; el consumidor sí debe comprobarlos. Cualquier corrupción contractual => REJECTED, no parcial benigno.

Todos estos resultados son numéricos. No naturalidad, ángulos certificados, enlace automático con fotos ni mapa reparado. Los rechazos humanos permanecen abiertos. No cambiar etiquetas ni tolerancias.

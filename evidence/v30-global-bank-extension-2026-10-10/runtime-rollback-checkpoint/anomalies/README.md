# EV95 water anomaly classification

Result: the 24 native `design_water_without_presence` samples split into two different cases. The classification is offline and does not establish what the renderer displays.

- **18 class-3 samples** have finite P and F values in all four adjacent cells and are contained at the sampled XZ vertex by at least one physical and one visible triangle from the compiled water-face index. Thus they are not static-geometry holes at those exact points. Their `SurfaceIsSea`/`SurfaceIsPond` flags were both false in the native readback. Across the containing physical faces, terrain-minus-face height ranges from about −1.130 m to +1.681 m: terrain is below all containing faces at 5 sample points and above all at 13. This confirms that terrain and water-face heights differ on both sides across the sample set; it does not prove a rendered defect or explain the flags.
- **6 class-1 samples** have P and all four F values NaN in each of the four adjacent cells, and no indexed water face contains the exact sample point. Five have no water-face bbox candidates in the four adjacent cells; `(424,1357)` has nearby candidates, with the closest candidate face 8.485 m away horizontally. Runtime no-fake-wave scalar level is about 0.652 m and configured sample sea level is 0.75 m; these values do not establish a water polygon or water presence. The group is consistent with a shoreline/class transition, but remains unresolved.

The 18 class-3 points form two nearby clusters around X≈2.36–2.48 km, Z≈6.88–6.92 km and X≈2.82–2.83 km, Z≈7.16 km. The class-1 points form a small cluster around X≈8.11–8.15 km, Z≈9.72–9.75 km plus `(4668,9432)`.

The exact-point test queried the four cells adjoining each native grid vertex from the COMPLETE EV93 index, then tested triangle containment in XZ; it did not treat bbox candidates as hits. The index records 18,024 water objects and 883,308 faces. Its source WRP SHA is `3071395e…eff1f6`, matching EV95 `stage.json`, and its water PBO SHA `3946db8b…02ae14` matches EV95 deployment. The staged world contains 18,033 preserved objects; the index intentionally covers the 18,024 objects whose model path identifies `baltic_water_v30`, not the whole world-object set. The other nine are outside this water-face index, so this query cannot classify any anomaly against those objects.

The EV95 native readback is `PASS_EV95_WIDE_NATIVE_READBACK`; its anomaly definition is class 1/3 with both runtime presence flags false. EV93 had 26 such samples; 23 coordinates overlap EV95, EV95 adds `(475,778)`, and EV93-only samples are `(875,231)`, `(875,250)`, `(879,218)`. This is a change in the sampled anomaly set, not evidence that the three vanished or one new point is a geometry defect.

For a decisive follow-up, sample a small sub-vertex grid around the 6 class-1 points and one class-3 cluster, recording flags, scalar water level/depth, and position against the same fixed terrain. Keep the two categories separate: investigate absence/shoreline behavior for class 1; investigate why flags remain false despite compiled face coverage for class 3. No water, terrain, P, or F values were changed in this analysis.

Reproduce with `classify_anomalies.py` using Python 3.10 + NumPy/Shapely. It pins the EV95 candidate arrays, native snapshot, verifier/report, index manifest and builder; it rehashes the read set and face-index shards after the query batch. Outputs are `classification.json` (per-sample exact faces, nearest candidate, adjacent P/F values and hashes) and `classification.csv` (compact table).
